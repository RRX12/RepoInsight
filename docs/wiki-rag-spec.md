## 1. 背景与目标

当前 Wiki 基于章节生成 Prompt 进行单轮 RAG。改造目标：让每章获得足以解释机制的源码上下文，减少函数截断、重复片段、检索被写作要求干扰和跨文件关键证据缺失。

验收关注：关键问题覆盖、源码位置准确、版本一致、关键连接有据、预算可控。文档变长或引用文件更多不是成功标准。

当前已检查的实现边界：

- backend/app/deepwiki.py：Wiki 任务提交、状态轮询与缓存读取；GitHub Wiki 旧契约不绑定 commit，不能标为固定版本证据。
- backend/app/analysis.py：先保存 Wiki，再执行共享源码调查及优化分析。保持这一行为。
- backend/app/code_retrieval.py、source_reader.py：原始源码检索与固定版本补读，需优先复用。
- scripts/deepwiki_raw_index.py：已有不可变 manifest、Embedding 指纹、词面/向量 RRF 融合及新向量预算；不要将已有能力重新描述为新增。
- scripts/deepwiki_raw_routes.py、install-deepwiki-retrieval.py：原始检索扩展安装与服务契约。
- scripts/deepwiki-local.patch：本地 sidecar 适配。仅修改 data 下的安装副本不能算完成，必须提供可复现、受版本检查保护的仓库内安装/补丁方式。
- sidecar 基线在安装脚本中为 d92819a9c9f3b99416e3580ff235fc9d3adf8b89；执行时核实。
- sidecar 的 api/services/wiki/tasks.py、prompts.py、api/services/research.py、api/rag/pipeline.py 为 Wiki 生成调查入口。

## 2. 最终生产链路与集成决策

保留现有 sidecar Wiki 任务、目录规划、页面保存和进度机制。在其逐章生成位置接入新的上下文准备流程；新路径不再把完整写作 Prompt 交给隐式检索。

章节候选仍由 README 与目录规划产生。本次不重建目录规划系统。新增章节计划根据已有标题、相关文件与少量真实源码线索提出问题，不将 README 的功能描述视为事实。

流程：

1. 绑定不可变源码快照及索引身份。
2. 解析文件、结构化切块并准备或复用索引。
3. 保留现有 Wiki 目录规划结果。
4. 每章规划 1–4 个核心问题与定位线索。
5. 定向读取与精确/向量检索，分别记录问题归属。
6. 去重、合并、局部扩展，形成 EvidencePack。
7. 检查关键问题覆盖；必要时最多两轮工具补查。
8. 将最终 EvidencePack 与写作指令交给模型直接生成页面。
9. 验证引用身份与范围、整理链接、保存页面及调查 trace。

不允许新路径准备完证据后，又进入 research_chat 对完整写作 Prompt 做一次不可见召回。复用模型流式适配器时抽出显式上下文生成入口；旧交互聊天行为保持，未经验证不切换它的检索逻辑。

必须提交一项生产接线验证：触发真实 Wiki 页面生成入口（替换模型/Embedding 为离线 fake），能看到新切块/检索/扩展/补查/生成链路被调用；仅有独立工具或未接入主流程的模块不算完成。

## 3. 数据契约

以下为逻辑字段，复用现有模型并向后兼容扩展，避免创建平行事实体系。

### 3.1 Chunk

- chunk_id：由仓库、版本、路径、字节范围、splitter_version 和正文哈希稳定生成。
- repo_identity、revision、index_id、file_hash。
- path、language、kind：function/method/class_header/top_level/document/fallback。
- symbol、qualified_name、parent_symbol_id（可空）。
- start_byte/end_byte：UTF-8 字节半开区间；start_line/end_line：1-based 闭区间。
- parent_start/end：可用于局部扩展的父级源码范围，不保证父块有独立向量。
- text：原始源码连续片段；必须能从对应版本原文件精确截取。
- embedding_text：可由路径、限定符号名、签名及 text 组成；与原文分开，不用于源码引用。
- content_hash、embedding_input_hash、splitter_version、parser_version、parse_status。

重复正文可以复用向量，但不能合并不同路径的证据身份。相同名称不得视为同一符号。

### 3.2 ChapterPlan

- chapter_id、title、scope、candidate_paths。
- questions：1–4 项，每项 question_id、question、importance(core/supporting)、path_hints、symbol_hints、semantic_query。
- 假设必须明确标记为待验证；不默认项目具有队列、重试、事务等机制。
- schema_version、prompt_version、输入摘要哈希。

初始每个问题最多一条短语义查询；不自动生成同义词查询列表。路径/符号来自模型时必须校验或通过搜索确认。问题重写仅在已有失败或新源码线索支持时发生。

### 3.3 EvidencePack 与 Coverage

- evidence_items：稳定 evidence_id、固定版本、路径、真实范围、原文哈希、原文。
- retrieval_hits：原始命中范围、渠道、排名、所属问题；与扩展后范围分开。
- expansion_records：扩展理由、扩展范围、增加 Token、是否截断。
- question_coverage：supported/partial/unresolved，不用相似度分数替代支持程度。
- gaps：具体问题、为何影响结论、拟补查动作、重要性、当前状态。
- 不将“未找到”解释为功能不存在；源码存在、实际集成、测试定义和测试通过分开。
- retrieval_status、stop_reason、usage、remaining_budget、未读范围和异常。

模型只允许引用已有 evidence_id；服务端将其解析成固定版本来源链接。引用在范围内不等于结论正确，两者分别记录。

## 4. 六项改造的具体要求

### 4.1 结构化切块与来源元信息

第一版正式覆盖 Python、JS/JSX、TS/TSX 与 Markdown；其他语言和解析失败文件支持显式 fallback。采用一个集中维护的结构提取层；可以使用 Tree-sitter 支持上述代码语言，固定兼容依赖版本。不要同时引入多个功能重叠的解析框架。

处理规则：

1. 普通函数/方法保留完整定义、装饰器和直接关联注释。
2. 类头、继承声明及属性与方法主体分别处理；避免完整类与所有方法都重复 Embedding。
3. 大函数按语法子块边界拆分。过大的单个子块才回退到文本窗口，保留父函数范围和原因。
4. 顶层初始化、注册、赋值不能因只提取函数而遗漏。用覆盖检查处理未被结构块包含的非空区域。
5. Markdown 按标题层级分块；长章节继续限长切分，并保留标题路径。
6. 回退切块按 Token 预算控制，重叠限量；记录 fallback，而非伪称结构化解析成功。

初始可配置值：目标 600 Token、单块最大 1200 Token、fallback overlap 80 Token。它们是试运行参数，不是已证明最优值。小函数不必凑满目标长度。使用同一个明确版本的 Token 估算器；无法精确计数时标记 estimated。

范围计算不能通过全文 find 猜测重复片段位置；优先使用解析节点的字节范围，回退 splitter 返回准确偏移。覆盖 Unicode、CRLF、重复片段、多行装饰器与嵌套函数。

### 4.2 检索 Prompt 与写作 Prompt 分离

拆分三个职责：chapter_plan、coverage_review、page_write。模板复用已有白名单管理方式。

- chapter_plan 输出结构化 ChapterPlan，不写正文。
- search 工具只接收短查询、路径/符号线索，不能包含 Mermaid、语言、表格、字数等通用写作要求。
- page_write 接收章节目标、最终证据与未解决问题，直接生成内容，不再隐式触发检索。
- 删除新路径中“已看到关联文件全文”“必须引用至少五个文件”等不符合实际上下文的要求。
- 上下文不足时不得调用旧的无上下文降级来生成似乎完整的文章；输出范围受限的页面或明确失败状态。

### 4.3 章节问题拆解

每章一次计划请求，基于标题、规划给出的文件和预算内的定位材料生成 1–4 个互补问题。简单章节允许一个问题，不机械拆成入口/状态/异常四项。

路径提示先验证存在；大小合适的关联文件直接读，较大文件查看符号/搜索片段。初始最多选四个关联文件，不能预读所有候选文件。

每项问题绑定独立 ID。去重重复问题，限制 semantic_query 为 300 字符、避免泛化关键词堆叠。格式不合格最多共享一次修复机会；仍失败则该章节显式失败，不能静默换成未经标注的模板文章。

README 与源码冲突保留在 gaps；章节核心主题无证据时，缩小描述范围或标记材料不足，不强行填充。当前阶段不自动重写整个 Wiki 目录。

### 4.4 精确搜索与向量检索结合

优先复用 CodeRetrieval、SourceReader 及 raw index 已有 RRF。不得将当前简单词面计分声称为 BM25。

- 已知合法路径：直接读取对应快照，不做向量查询。
- 已知符号/配置键/路由文本：精确搜索先定位；搜索结果仍需读取上下文。
- 功能描述：向量检索；可同时使用现有词面检索融合。
- 精确搜索须能独立于 Embedding 运行，不能为查一个已知标识符强制付费生成查询向量。
- 融合保持各渠道排名和问题归属。沿用 RRF 参数时记录参数；不同分数不能直接相加。
- 初始每问题每渠道最多 8 个候选，合并后每问题最多 12 个；全章最多 40 个唯一候选。
- 通过问题轮询和多样性选择装入上下文，避免首个问题耗尽预算。已验证的关键入口材料单独保留，但“目录猜测的入口”不能无条件强制入选。
- 本次不新增 Cross-Encoder 或 LLM reranker；预留简单接口即可，不引入闲置依赖。

### 4.5 命中块去重、合并与局部扩展

先按同仓库、同版本、同文件处理，再按源码区间去重。不能跨版本合并，也不能仅靠内容哈希丢弃不同来源。

1. 同范围重复命中保留一次正文，合并问题归属和渠道信息。
2. 重叠范围取并集；相邻范围只有间隔较小（初值不超过 8 行）、属于同一结构且预算允许时合并，并读取真实间隔内容。
3. 小函数命中后补齐父函数；父函数超过单证据上限则仅补签名、相关分支和必要定义，标记不完整。
4. 方法按需要补相关属性初始化；不默认读取整个类。
5. 影响结论的外部调用目标记录为 gap，不无限递归扩展。
6. 最终摘录总量按唯一来源区间计费；实际进入模型的重复文字也须计入输入预算，不能因逻辑去重漏算。

每条 evidence 初值最大 2000 Token；不得为了限长截断后仍声称提供完整函数。连续片段与非连续片段分别记录来源，不能拼成虚假的连续行号。

### 4.6 有界 Agentic RAG

采用单个章节调查循环，嵌入现有页面任务，不创建新的会话系统或多 Agent。LLM 判断缺口与选择动作，程序执行白名单工具、预算与版本检查。

可用工具：search_exact、search_semantic、read_range、read_symbol（有索引时）。允许读取同快照配置、注册和测试源码；不执行导入代码，不执行任意 shell，不访问模型提供的任意 URL。未可靠解析的调用目标只作为候选。

覆盖审查返回：各问题状态、已有证据 ID、关键缺口、最多三个工具动作，或 finish。动作必须包含 gap_id、purpose 和严格参数。程序验证路径、范围、工具类型、去重及预算后才执行。

循环规则：

- 首轮检索及扩展后做一次 coverage_review。
- 仅当缺口影响核心结论且有可执行补查动作时继续；可选细节不强制触发。
- 最多两轮补查；每轮后重新检查，最多三次 coverage_review。
- 同一快照下相同查询/读取范围命中缓存，不重复计为新证据。
- 一整轮未增加有效证据且未解决缺口时停止；不能通过改换同义句绕过无进展限制。
- stop_reason：sufficient/budget_exhausted/no_progress/unresolved/unavailable/cancelled。
- budget_exhausted 或 unresolved 时允许写有据的有限页面，必须展示未确认范围；无有效证据时不生成实质性项目结论。
- 格式修复、网络重试也计入模型请求上限；取消检查在调用前后及写入前执行。

## 6. 版本、缓存与迁移：必须先解决的依赖

结构化分块会改变 Embedding 输入，旧向量不一定能复用。必须在任何代码 Embedding 前执行 dry-run，报告候选块数、命中缓存数、所需新向量数。预算不足返回明确错误；不得自动改为全仓付费构建，也不得把旧向量标为新分块结果。

分开处理三类缓存：

1. 向量缓存：由 embedding_fingerprint + 完整 embedding_text 定位，可跨快照复用相同输入的向量。
2. 索引 manifest：绑定 repo、revision、文件哈希、parser/splitter/embedding 配置与 schema 版本。
3. 章节缓存：绑定工作区、快照、索引 ID、章节计划、Prompt/模型/预算配置与增强流程版本。

增强 Wiki 必须使用 RepoInsight 解析的固定 SHA。扩展 sidecar 内部任务契约接收 revision；固定快照路径/工作树与普通 branch 缓存隔离，不 checkout 或覆盖用户工作目录。底层目录规划、读取、向量检索与引用都使用同一快照。

增强 Wiki 的任务键、缓存键及文件引用必须包含版本与流程版本；旧 unknown Wiki 仍可查看，但不能命中新增强结果或冒充其来源。旧入口传参保持兼容。旧默认缓存命中必须先辨别 legacy/enhanced，不能在新流程开始前提前返回旧 Wiki。

增加单一开关 WIKI_RETRIEVAL_MODE=legacy|enhanced，配置默认 legacy，测试明确选择 enhanced。增强路径不可用时显式报错，不静默退回 legacy 后声称增强成功。待离线门槛及真实样本评测通过再切换部署默认。回退开关不删除旧索引和历史页面；记录兼容路径及删除条件。

## 7. 生命周期与安全

- 复用现有任务互斥、取消、重试与重启 interrupted 行为，不启动第二套后台任务。
- 在每次模型调用、源码工具调用、阶段提交前后检查取消与任务输入指纹。
- 本地取消后不再启动新动作、不接纳晚到结果；不能声称已停止外部计费。
- 相同任务身份下，仅保存已验证的完整章节供重试复用；半成品和失败占位页不可标成功。
- 旧前端继续读取 generated_pages；可增加每页 coverage/status，不破坏既有字段。总进度区分处理完成数与成功数。
- 仓库文本、注释和 README 只作为数据；其中要求改变工具权限、读取秘密或忽略约束的指令不可执行。
- 安全路径检查复用现有实现，并覆盖真实路径、符号链接越界与敏感文件排除。所有读取限定目标快照。

## 8. 实施阶段与阶段验收

### P0：基线和生产接线设计

确认实际生产调用链、sidecar 版本、现有检索与预算消费者。记录哪些代码能复用、哪些需要适配。建立旧流程离线回归样本；不删除旧行为测试。确定补丁安装方式和开关，不修改用户 .env。

完成标准：有入口级 fake 集成测试骨架；明确新模式不能误命中旧缓存。

### P1：结构切块、契约和索引版本

实现结构提取、准确位置、fallback、元信息、Embedding 输入分离及 dry-run。升级索引 schema，保留旧索引读取或明确兼容错误，不就地覆盖。

完成标准：结构与位置测试通过；预算 0 时发生缺失向量，Embedding fake 调用次数必须仍为 0；重复准备复用相同索引。

### P2：章节计划与多路检索

拆分模板和模型输入，接入合法文件定向读取、精确搜索与已有向量/词面融合。问题归属贯穿结果，不把输出格式指令送入查询 Embedding。

完成标准：测试捕获实际 embedding_query，确认无写作指令；已知路径/符号的精确定位不触发语义 Embedding。

### P3：上下文组装

实现区间去重合并、局部扩展、问题间分配预算、来源记录与证据包。

完成标准：重复块不重复占用正文；必要函数边界补齐；超长父函数不突破预算；不同版本不能混合。

### P4：Agentic 补查与页面生成接线

实现严格工具动作 schema、覆盖审查、最多两轮补查、无进展停止、预算守卫和最终直接生成。新路径引用验证、固定版本链接与未确认说明同时完成。

完成标准：入口集成测试中首轮缺失的关键定义可补读；同时覆盖首轮充分、无进展、预算耗尽、工具失败和取消等分支。没有隐式第二次写作 Prompt 检索。

### P5：回归、评测和文档

运行定向后端测试、sidecar 离线实集成及受影响前端检查；执行统一 checks（可用环境下）。更新 architecture、PRODUCT、DECISIONS 和 STATUS 当前节。README 仅描述已实现且注明验证范围的能力。

## 9. 必需测试与评测方法

所有默认检查离线，使用 fake embedder 与脚本化模型响应。至少包含以下行为场景：

1. 小函数、长函数、嵌套函数、装饰器、类属性、顶层注册；TS/TSX 与 Markdown；解析失败回退。
2. Unicode/CRLF/重复文本位置准确；所有源码块可从快照精确重建。
3. 文件或分块配置变化使 manifest 变化；Embedding 配置变化不误用旧向量。
4. 正文一样但来源不同：可共享向量但引用身份不丢失。
5. 已知路径、同名符号、语义描述分别走正确检索路径；相似度不是置信度。
6. 多问题材料分配、重叠合并、父级扩展、超限和未读范围。
7. 计划中的不存在路径、未提供 evidence_id、越界行号被拒绝或记录为缺口。
8. 补查发现定义后正确停止；循环同查询、无进展、两轮上限及请求上限。
9. 检索失败不得静默转成无证据完整页面；无有效材料不产生事实性文章。
10. 取消/更正/删除/晚到结果、重试复用、工作区隔离不回归。
11. legacy 缓存可查看但不被 enhanced 命中；增强错误不伪装旧流程成功。
12. 源码中的恶意指令不改变工具白名单或读取范围。

准备至少 12 个离线章节案例，覆盖单文件、跨文件、混乱 README、错误候选路径、同名符号、配置分支、部分功能未接入、长函数、无答案等。每个案例人工定义核心问题、必要证据组、可接受替代来源和不应声称的关系，避免测试只检查实现自身生成的 ID。

对照组：A 旧流程；B 结构切块+计划+检索+扩展；C B+补查循环。采用同一快照和相当上下文预算。指标：必要证据组覆盖率、无关上下文比例、重复 Token 比例、错误引用率、补查新增有效证据、模型/工具/Embedding 次数与耗时。离线模型桩只证明编排与检索行为，不能证明文章质量。

离线硬门槛：关键隔离/预算/来源测试全通过；fixture 中不可出现版本混用、越界引用或禁止关系；逐案例报告覆盖变化，已覆盖案例不得无说明退化。不预写“提升 30%”等成果。

真实内容质量评测作为单独命令提供，默认不执行。需显式模型服务与预算后，才运行同配置 A/B/C，比对问题回答质量、错误关系及成本。没有真实评测时，报告“离线机制验证通过，真实内容质量待验证”，保持默认 legacy。

## 10. 交付与完成定义

交付必须包括：

- 已接入 Wiki 主流程的实现与单一开关；可复现安装的 sidecar 变更，不仅是本地 data 修改。
- 更新后的锁定依赖、契约、模板、配置示例及索引迁移说明。
- 定向行为测试、离线入口集成测试、可复现评测命令及逐案例报告。
- 当前文档与兼容退出条件；真实服务未验证范围、预算限制和已知问题。
- 简短最终报告：改了什么、复用什么、实际测试结果、如何启用增强模式、是否需要新向量、如何回退。

不能以仅提供设计、只新增未接线模块、放宽旧断言、自动删除失败页面或伪造实际指标作为完成。
