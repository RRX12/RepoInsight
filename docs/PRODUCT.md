# 当前产品与验收

2026-10-14：中文、本地单用户、单后端进程 MVP，当前流程为公开 GitHub 仓库链接 → DeepWiki 项目全貌 → 项目提问与优化方向讨论。简历生成、简历审查、项目经历编辑器已退出产品；旧数据保留，历史产物只读 API 用于取回材料，不提供重新生成。

## 用户流程

2026-10-16界面：用户工作台统一暖白／墨绿视觉，顶部项目选择与岗位JD编辑保留；三个页面分别突出连接仓库、章节阅读、方案取舍，并显示当前连接仓库。桌面章节目录固定在阅读侧边，窄屏改为正文上方可滚动章节区。浮动讨论沿用移动、缩放、收起与取消能力；技术方案比较通过独立卡片区分。系统字体本地加载，无字体外网依赖。视觉呈现不改变生成、证据、历史及业务写入规则。

2026-10-15动态索引：enhanced可选择index_mode=auto，先核对固定版本索引及相同embedding输入缓存，只计算缺失的不同输入；本机已启用，默认统一安全上限10000个新向量／次（可配置），不要求每换项目填写数量。reuse_only保留原显式max_new_vectors（默认0）行为。auto按32个输入为一调度窗口、最多2个请求并发，每个API请求仍为单输入；没有假设供应商支持批量输入。超过全局上限在调用前失败，不以多轮执行绕过额度。

索引准备显示缓存复用／新完成／待补齐数，已完成向量逐个持久保存；失败或停止后新分析／同策略安全重试会只补剩余部分，完整manifest只在全量有效后发布。限流和额度失败保留缓存并明确失败，不做无限重试或未经验证的自动加并发；实际SDK内部重试／计费仍需服务观测。默认auto等待最多7200秒，超时请求取消sidecar，不承诺在途外部计费停止。优化调查复用Wiki已完成的结构索引，不另外构建一份旧分块索引。真正调用模型／embedding由用户发起分析触发，本次改造未实际调用。

分析进度标题旁显示实时秒数和展开箭头，可查看可读阶段摘要；成功、失败、取消后固定本次用时，重试从新一轮计时。排队时显示等待至今的时长，开始后改为实际执行时长；未记录结束时间的旧历史不伪造用时。清除所有项目分析历史会删除已结束的项目Run及其内嵌报告／Wiki；正在执行或尚未释放占用的任务保留。仓库、岗位JD、对话、独立保存的方向、证据与退役简历Run保留。

2026-10-15新增可选增强Wiki（默认 `WIKI_RETRIEVAL_MODE=legacy`）：固定SHA目录规划 → 每章1–4个问题 → 路径／符号定位或短语义查询 → 去重局部源码证据 → 覆盖审查 → 最多两轮补查 → 直接写作及引用校验。增强不把写作格式送入检索，不暗示已读取整个文件／仓库；不足的章节显示未确认范围、停止原因。引用检查通过不等于关系语义或运行效果验证。当前增强仅公开GitHub固定SHA与DeepSeek适配器，上传和其他provider必须显式使用legacy，不静默回退。原问答／优化讨论链与优化调查预算保持独立。

增强默认每章：模型6次（含一次共享格式／引用修复）、工具20次、语义查询6次、8个源码文件、最多3次审查／2轮补查；初查8000、总证据12000、单证据2000、模型输入18000、输出4000。估算采用UTF-8字节保守上界，不是服务usage。最多12页，任务章节模型72次／语义72次，目录模型最多2次；可显式调低或按契约配置提高允许项，全部配置冻结到任务身份。结构chunk目标600／上限1200／fallback重叠80。代码新向量默认0，在调用前dry-run报告候选／缓存／缺失，不足明确失败；query embedding单独计数，未知Token为null。

仅覆盖充分且引用核对通过的完整章节可自动复用；有限页面可展示但不命中完成章节缓存，整Wiki含有限页时不作为完整缓存短路新任务。取消、更正、删除及输入指纹变化拒绝晚到结果，不保证外部计费已停止。默认开关保持legacy，离线12例并不证明真实文章质量；启用／回退及限制见architecture，逐例结果见evaluations/wiki-rag-offline.md。

用户页有项目设置、项目全貌、优化大方向三个入口。项目设置分两步：先保存GitHub仓库链接，再填写可选岗位JD。第二步下方为“分析项目全貌与优化方向”和“跳过”；跳过明确清空本次岗位JD并按“项目工程优化”分析，旧JD版本保留。顶部“修改岗位JD”紧邻“＋ 新项目”，打开编辑窗口，可保存或取消；保存复用版本化target接口，不自动分析，不覆盖历史报告。移除用户页顶部“过程后台”入口，原直接后台地址保留排查。分析任务先保存 Wiki，再进行固定 SHA 源码调查及优化必要性评审；优化失败时 Wiki 仍可阅读、问答，重试复用已保存材料。

项目全貌左侧列出项目定位和具体 Wiki 章节，点击切换右侧完整 Markdown、表格、代码和按需架构图。当前章节自动作为问答辅助材料；Wiki 版本未知不能视为当前 SHA 源码。

项目全貌和优化方向页提供浮动聊天框：拖动标题移动、拖动右下角调整大小，或按放大/缩小按钮改变窗口尺寸；支持收起/展开和键盘方向键移动，并限制在视口内。收起保留会话和在途回答，可展开停止；离开页面取消接收并显式请求取消。问答使用原 wiki 会话，优化讨论使用原 discussion 会话，互相隔离，刷新恢复已保存消息。

每个优化方向可点击“讨论此方向”，本轮提交其 ID，服务端只读取同工作区的方向标题、方案、问题、取舍和实施状态，明确标注为建议而非成果。更正或删除方向后旧回答不得落库。讨论只用于理解、比较和取舍，不自动采纳、编辑方向或报告完成。个人约束与讨论笔记独立保存，详见 memory/README.md。

系统优化建议仅供参考；用户可保存、编辑、软删除自己的完整方案，选择表示准备采用，完成只能记录为用户报告。计划、源码存在、集成与实测分开。JD可用于发现能力深化与合理扩展并参与排序；不创造已有缺陷，不把岗位要求当作项目已实现能力。

## 事实与预算

固定版本README／目录 → 共享源码调查及独立事实核验 → 不可变项目分析包 → 批量候选规划 → 有界源码／公开资料调研 → 综合取舍与实施方案 → 可选一次定向补查及修订。优化不默认追加独立模型评审；程序校验来源与结构不等于独立语义认证。允许零候选并说明原因。

准备＋优化整体最多12次模型请求、250000已报告Token保护保持；优化正常2次语义调用，可选1次补充，最多4次尝试（含失败和全流程最多一次格式修复）。准备调用单列，不能称整次任务仅2次；源码工具32次、默认12文件（最多16）、总摘录30000字符、初查20000，补查预留10000；单阶段160000 UTF-8字节。最多12条初查和4条补查。新代码向量预算默认0只复用，query embedding 单独记录。API usage 未知为 null，不报告为零。无服务明确失败，不用 AST 或规则稿冒充模型分析。

不执行导入源码、README或附件；材料没有工具权限。单主 LangGraph 讨论 Agent、按需 Skill、SQLite 记忆保持。共享调查记录索引身份和未读范围，候选命中不是事实证明；源码实现、归属与验证层级独立。

## 生命周期与兼容

架构任务支持取消、失败/中断重试，单工作区互斥；重启标 interrupted，不自动重放付费请求。方向表单继续版本/CAS/幂等与历史；讨论继续 revision/指纹、停止、删除与晚到结果检查。取消是否停止上游计费未知。

旧 POST artifacts、interaction/editor/review/generate/decision 已移除，写作 Skill、HR选题/双审模板、规则简历和评测脚本已删除。Artifact/贡献/指标/旧交互存储及迁移保留，不删除用户历史；GET artifacts 及 export 只读。旧简历 Run 禁止重试。上传、旧离线分析和旧只读消息接口继续兼容，不是当前产品主入口。

验证范围见 STATUS.md；离线通过不代表真实模型内容质量。未经本次授权不调用付费服务或推送远端。

本机2026-10-15用户明确选择最高Wiki资源预算（详见STATUS）；章节呈现恢复完整技术说明、表格及证据支持的Mermaid图示。最高预算不等于实际调用量或质量保证，来源和未知范围边界保持。


## 优化规划 V2（2026-10-16）

候选涵盖engineering_fix／capability_deepening／feature_extension，最多6个、最多3个重点调查及3个详细方案，允许0个。不推荐项仍在候选总览保留理由；条件建议写触发条件，证据或关键假设不足先验证。时间／技能／环境可选、参与版本指纹，不推断用户条件。技术选项比较现状／简单方案与建议设计，描述源码接入、分步实施、失败处理与验收；未运行测量不报告效果。

新增预算见.env.example的OPTIMIZATION_*，程序校验范围并实际限制；序列工具执行并发为1（不超过配置上限3），轮转候选避免首项占尽预算。源码32次／文件与30000字符全局保护继承准备消耗；工具不调用生成模型。候选命中不等于已读证据，源码按固定版本重读。外部Tavily默认关闭，开启后查询／正文默认各6次，搜索可能收费；不启用answer／研究Agent。外部访问公网HTTP(S)，逐跳及DNS／连接IP检查，拒绝私网／凭证URL，正文限500KB／12秒／3次跳转；正文按完整段落加载，未读范围明确记录。外部文献与本项目源码分离，摘要仅线索，版本未知写null，外部失败不阻断有依据的受限建议。

新报告schema为optimization-v2，保留旧Overview读取及旧报告／用户方向；Run.result.report保存结构化方案，Improvement.details保留兼容字段及v2_plan、candidate_id、run_id和来源摘要，不新增数据表／状态枚举。讨论仅载有界方向摘要，完整方案hash检查晚到结果。生成不等于采纳或完成；旧用户方案不被替换。

规划／最终报告仅在身份匹配时复用；身份包含约束、更正、JD、版本、模型、模板、配置及共享包，内容哈希与工具／来源指纹记录在缓存。外部缓存24小时，OPTIMIZATION_WEB_REFRESH=true显式绕过报告／外部缓存。准备、优化、embedding、web和Wiki用量分开；无法获知仍为null，页面列本轮模型记录，不把缓存历史用量当本轮费用。
