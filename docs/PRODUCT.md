# 当前产品与验收

当前为中文、本地单用户、单后端进程 MVP。入口是公开 GitHub 链接和岗位/JD；DeepWiki-Open 全面 Wiki 和架构必要性评审提供项目理解材料，用户通过讨论、更正、材料和确认贡献生成项目简历参考稿或个人简历。历史流程及预算变更见 DECISIONS.md，本文件描述现行能力。

## 产品边界

- 项目全貌先于 JD 选材：产品用户、背景、闭环、架构和关键机制保持独立；JD 分别参与候选筛选、必要性检查后的方案排序、事实不变的简历主题选择。
- 建议针对模块、架构和能力方向，先核对业务问题、已有解法、必要性、替代方案和代价，再关联 JD；最多三项，允许不改，不为关键词强加 Agent/MCP/Skill。
- 上游能力与用户贡献分开；讨论、尝试、实现、验证分开。更正保留历史，使依赖草稿待复核；用户数字保留来源和验证状态。
- 单主 LangGraph 讨论 Agent 与按需 Skill 保持；没有新增自主子 Agent、图谱或队列。导入仓库和附件均为数据，不执行其代码，不改变工具权限。
- 本地单用户，无认证、自动编码/运行、私有 Git 克隆、PDF 投递。旧 ZIP、搜索、AST 实践 API 保留兼容，非当前页面入口。

## 简历行为

project_reference 以完整项目为主体，融合原有架构与用户补充，不宣称上游全由用户原创；没有讨论或优化也可依据已保存 Wiki 生成。personal_resume 的亮点需绑定当前确认贡献。模型稿只将有支持的已实现内容放正文，设计计划及缺口放正文外；规则参考稿显式标明未实现设计，保留离线/演示用途。

表达为项目简介 → 1–4 条加粗技术主题 → 可选项目成果，采用简洁 STAR；聚焦技术、设计思路与有依据结果，不列函数、端口等细节。模型读取 resume_composition Skill 和写作模板，流程为：

全量有效 Wiki 分块映射 → 无 JD 全貌 → 最多 6 项岗位中性调查 → 相关 Wiki 召回/邻居 → 通常 6–10 候选（小项目允许更少）→ 候选缺口驱动固定 SHA 源码补证与已有卡片补全 → 独立 claim 核验 → 主题合并/选题与职责覆盖 → 结构化 Draft → 独立 HR/技术审查 → 最多一次补证重选和修订 → 确定性 Markdown。

同一链路的原有机制与优化合并为主题，事实状态和归属不合并。每段关联 claim，数字关联指标及口径。未命中表示未知，不代表不存在；支持程度、实现阶段、归属和验证层级独立。源码存在不等于集成，测试定义不等于通过，用户报告不等于系统测量。Wiki 版本可能未知，不追认固定 SHA。

最多 64 映射批次、每批两块且一次引用修复，总映射请求上限 128；后续默认 16 请求，RESUME_GENERATION_CALLS 限定 8–20，结构修复和重选计入；源码工具预算 32 调用，GitHub 适配器最多三次 HTTP 尝试。最多两轮写作，首稿一次独立HR/技术双审，修订稿做程序契约校验及一次独立HR/技术复审，无无限循环。每阶段输入 160000 UTF-8 字节和映射事实包 85000 字节的既有预算保持；不足明确失败，不裁掉尾部冒充完整覆盖。字节估计不是实际计费 Token；API 用量未知不报告为零。

HR 与技术意见通过不同请求产生，互不读取判断，仍使用同源模型。expression、candidate_omission、mechanism_missing、fact_attribution、needs_evidence 意见及阻断标志如实展示（important_omission 保留历史兼容）；旧 audit 兼容展示。未通过稿为 needs_review，模型异常不冒充规则稿；人工仍须复核事实和经历。

## 生命周期与验收

- GitHub 链接校验、工作区隔离、固定 SHA 只读补证，导入源码不执行；真实服务缺配置明确失败，无 AST 兜底；演示标注不是真实仓库分析。
- 生成传递当前编辑中的岗位/JD，包括清空 JD；角色为空返回校验错误，不退回旧角色。两个 JD 写入口共用版本、requirements、历史和失效逻辑。
- 同工作区产物请求串行；其他运行任务占用工作区时拒绝新生成。取消后仍等待已发模型 HTTP 返回，下个阶段停止且不落稿；停止期间拒绝新生成。
- 通用分析队列不可重试简历 Run；通过原产物请求重试，同输入幂等，输入变化需新键。重启将未结束任务标为 interrupted，不自动重复付费调用。
- 材料冻结指纹和保存前核对保持；运行中更正不能保存旧材料稿为当前版本。历史稿可预览导出，不补造证据映射。
- 模型客户端、项目契约、材料收集和缓存配置共享；旧 Markdown 基线只用于明确的评测比较。规则参考稿继续提供独立的离线/演示路径。

具体已验证范围和真实质量限制见 STATUS.md、resume-quality-progress.md 与 code-review.md。离线契约/E2E通过不证明模型对所有仓库和岗位都能准确理解。

## 机制卡片与定向修订（2026-10-11）

候选包含可选的业务问题及problem_claim_ids、atomic_fact_ids、带claim映射的mechanism_steps/exception_boundaries、investigation_questions/source_paths、contribution_claim_ids/result_claim_ids及结果来源；没有依据不要求填满。卡片内引用属于该候选，结果来源必须存在，失配只允许一次关联修复，不改变原陈述。新契约版本resume-quality-v2，旧审计不迁移。

源码补查在发现之后，使用候选问题/符号/路径，不再先按JD扫一批源码；累计最多12文件（配置上限16）、30000字符（初查20000，预留10000），两轮共用已读路径/预算，初查保留约三分之一文件名额供一次增量发现。无问题不补查，不在固定树中的路径明确not_found；源码缺失不证明全仓不存在。补全记录历史，可用显式关联替代事实/候选，也可增加有证据的原子步骤；不新增另一条生产流程。

写作只接收已选卡片的supported+implemented事实；移除未核验机制摘要、个人声明、自由选题大纲/理由，业务问题也须绑定支持事实。已选卡片中的未支持步骤被排除，成果可空。未绑定当前确认贡献的模型个人标签被保守降为归属/实现/验证unknown并留trace，不提升事实或补造贡献。

表达问题仅改写；事实/归属问题有claim ID时局部重核、必要时重选；机制缺失/候选遗漏最多一次定向补证与增量发现，再独立核验/重选。结构/关联/事实修复均计入原有生成预算，仍最多两轮写作及每稿一次双审。评审只看已支持已实现的事实和单列状态限制，不将用户提议作为现有架构。角色审查是辅助反馈，不是验收。具体真实失败与未验证修正见resume-quality-progress。


## 当前生成流程 v5（2026-10-12）

沿用原生产入口：原文索引及Wiki映射 → 独立全貌/JD调查 → 原文检索和候选 → 候选问题补查Wiki/固定SHA源码 → 技术补全及独立核验 → HR选题 → 单次统一写作 → 独立HR/技术评审 → 有明确动作最多修订一次。删除HR/技术各拟完整稿再合并的生产步骤；历史双稿audit只读保留，不迁移。

角色模板位于backend/prompts/resume；白名单绑定输入、schema和零工具权限。HR接收职责、已核验主线和候选；技术调查接收原始证据和缺口；HR评审不收源码，技术评审收相关来源。写作Skill只负责表达。模板缺失/版本错误在模型调用前失败。每任务记录模板/材料哈希与上下文，usage缺失记未知。

索引保留原文起止、标题层级、前后邻居、来源内容哈希和超长块拆分；词面召回保留未读与预算省略编号，不称语义覆盖。全量映射继续作为当前全貌来源，原文按JD及候选问题独立检索，不以摘要为唯一证据。源码窗口按问题词覆盖与执行条件排序，不再固定只取文件最早3个命中；仍最多3个窗口，未读命中明确记录。

新证据可新增/拆分/纠正主题；旧claim不能原地改陈述，新ID可显式supersedes。整主题被显式替代时其无当前消费者的旧claim归档，不能猜新旧事实等价；完整旧版和替代关系保留。活跃结果仍需完整证据/贡献校验。

事实门禁与内容评分分开。内容评分五项权重25/30/20/15/10，每项0–4，目标75且岗位/深度各≥3。HR评分岗位/主线/可读性，技术评分深度/覆盖；缺独立基准时为暂定自评，缺评分明确未评，不能宣称人工验收。修订后未再语义评审须明确pending，不把首稿分数移作最终稿分数；低分且无可执行意见不触发重复写作。

缓存复用原Wiki和固定SHA源码缓存；阶段缓存以工作区/快照/版本、角色模板及实际输入、模型配置为键，完整流程通过后才提交，失败流程不缓存新阶段。生成与接受建议继续执行指纹/CAS，不因缓存跳过取消检查。JD/指标变化可复用不变的上游证据，但当前编辑器仍按整稿保守标待复核，未实现句级依赖失效。
