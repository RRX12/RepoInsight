## 使用

用户页项目全貌和优化大方向的浮动聊天框使用相同能力、独立wiki/discussion会话。刷新恢复；讨论不自动修改JD、指标、贡献或实施状态。简历生成及编辑入口已移除。拖动标题移动、右下角调整尺寸，放大缩小/收起按钮控制窗口；离开页面主动取消接收并发送取消请求，收起保留会话。

- 普通问题仅保存问答。`约束：只考虑本地部署`记录会话约束；`项目约束：…`明确授权同项目其他会话读取；`讨论笔记：…`和`待解决问题：…`记录讨论态度/未决事项。
- 自然语言出现“记住、更正、纠正、继续研究、以后都、整个项目、补充约束”时，最多一次结构化解析，与回答调用分开；不每轮生成摘要。解析复用现有写作模型配置，普通问答使用DeepWiki。自动提取的用户条目必须有本轮原话及来源，不能由模型扩权。更正已有笔记也可直接使用界面按钮，无模型请求。
- “已保存约束与讨论笔记”查看当前有效项、来源类型和待复核状态，可更正、撤回、标记问题已解决。撤回保留审计，不再参与后续上下文；彻底删除原文用“删除会话”或“清理项目讨论记忆”。源码观察只能撤回，不能手改成已核验事实。
- 不自动按天删除。删除会话清理消息、派生记忆、全文索引、缓存及旧检查点；仅保留不含正文的会话墓碑。其他会话引用过已删笔记的派生回答也会脱敏，不通过旧回答恢复它，独立用户输入保留。业务审计嵌套保存过消息的部分脱敏，业务记录自身不删除。工作区范围笔记仍归属于来源会话；删除该来源会话后不继续共享它。
- 失败/取消输入可查看；部分流不保存为成功回答。重启把pending标失败，不自动重复付费请求。同会话一个在途问题，版本更正或删除会阻止旧结果写回。

## 数据与调用

`FloatingChat → DiscussionChat → conversations API → LangGraph(plan/source) → discussion_context → wiki_chat.stream → finish(CAS)`。会话、记忆与消息是SQLite中的唯一真源，没有第二份滚动摘要/检查点。原有源码缓存只存代码，不存讨论内容。源码观察附实际片段/路径/行范围/仓库/SHA，代码版本变化时显示needs_recheck，不用于新版本事实。

路由均在`/api/workspaces/{wid}`下：

| 方法/路径 | 用途 |
|---|---|
| POST conversations `{surface}` | 恢复当前wiki/discussion/legacy会话 |
| GET conversations/{cid}?offset=0&limit=50 | 分页消息、焦点、记忆、pending请求；limit最大100 |
| POST conversations/{cid}/turns | request_id、expected_revision、content、可选run_id/page_id/improvement_id；NDJSON流 |
| POST conversations/{cid}/cancel | request_id；取消幂等 |
| POST conversations/{cid}/memory | 显式条目增改/撤回/解决，带revision与request_id |
| DELETE conversations/{cid} | 删除当前会话及衍生内容 |
| DELETE discussion-memory | 仅清理本项目讨论模块，不删除项目业务数据 |

旧POST messages/wiki-chat/interaction/chat返回410；旧网页应刷新到新版前端，不把任意history回填为服务器历史。旧数据由003迁移进入legacy会话；API可读，原记录保留，不猜测成功轮次。新前端与新后端需要一起加载；本次未部署/重启现有服务。

## 预算与检索

`.env.example`给出近期10轮/4000、状态1200、历史2000、总输入16000、输出预留2000、窗口32768。当前按UTF-8字节保守估算，不声称真实token计数；安全余量1024。完整应用信封含规则/问题/来源/JSON协议一并校验。超限先丢旧历史/近期完整轮次/证据，必要约束或问题放不下则提示缩小范围。源材料被移出有ID记录，不静默截断当前问题。

历史按需要触发，对象/主题关键词与FTS5 trigram匹配；中文不足3字或FTS不可用时有显式关键词回退。只返回完整成功轮次，过滤被替代/撤回来源。普通追问用当前焦点补成查询，不预设机制已实现；未知对象可澄清。该规则覆盖常见工程词及引号中的对象，真实复杂指代识别仍需评测。

真实源码检索最多1个查询、3个命中、8次源读取，prepare新向量预算为0；代码观察复用必须同仓库/SHA/完整查询。DeepWiki问答实际发送一个有界上下文信封；其内部可能再次检索、拼接提示和调用模型，**内部token、索引SHA和计费取消均不能保证**，日志明确unknown。不是控制了DeepWiki完整模型上下文。没有真实usage时为null。

## 验证

- `python -m pytest backend/tests/test_discussion_memory.py -q`：M01–M20涵盖持久化、10轮预算、指代、切题、更正、隔离、版本、幂等、删除、非法引用、业务写隔离、失败/取消和中文检索；另有迁移和旧检查点清理、远端浏览器停止回归。模型/HTTP用mock，不证明真实意图提取准确率。
- `python scripts/check.py --e2e`：统一架构/后端/类型/隔离构建/浏览器检查，最终计数见STATUS。无付费调用，不修改生产数据。
- `python scripts/eval-discussion-memory.py`：40个合成多轮场景，A近期窗口、B加状态、C加按需历史与查询改写，共120次实际上下文组装；结果在[offline-results.json](offline-results.json)。模型未调用，无虚构答案。此处只测最终输入覆盖，不是回答正确率。

初次回放：36个允许组装的场景中，约束进入最终上下文A为24/36、B和C为36/36；需要旧历史的4例A/B为0/4、C为4/4；更正状态A为0/2、B/C为2/2。另4个并发/删除场景在每种变体拒绝组装。失败例和每例加载ID/估算量/耗时保留在JSON，不只给平均分。合成样本少，不能据此推断真实用户收益。

未验证：真实DeepWiki服务协议/真实模型提取与回答质量、真实token/端到端延迟；大量历史下SQLite扫描性能；多进程部署（不支持）。本次只在隔离库跑003迁移，未迁移用户生产库。真实A/B/C需相同模型、固定证据、人工盲评回答对象/约束/更正/状态保真/依据，获得一次新的有界付费授权后执行。
