# RepoCareer 项目讨论记忆系统实施规格

状态：待实现／待验收。本文是目标规格，不是现有能力说明。
版本：v1.0 · 2026-10-14
适用仓库：RRX12/RepoCareer，起点分支 codex/resume-quality。
历史核对基线：c1d033e6a284d08a3d5f86986242783d9c402697；执行时必须重新核对当前代码。

## 0. 给 Codex 的执行指令

请按照本规格实施项目讨论记忆机制。先读取当前 AGENTS.md、docs/PRODUCT.md、docs/STATUS.md 当前节和 docs/architecture.md，检查分支、提交及未提交改动；定位真实生产入口、契约、调用方和测试。复用现有实现，逐阶段完成代码、迁移、验证与文档，不停留在方案建议。

本次范围限定为项目理解与改进方法讨论。讨论不触发简历生成，不修改个人贡献、指标、JD、简历或方案实施状态；简历功能和显式表单入口保留。讨论可以记录“用户倾向继续研究某方案”，不能将其转换成已采用、已实施的业务状态。此产品边界来自用户本次澄清；若旧产品文档不同，同步修改相关讨论范围说明，保留其他模块职责。

不安装 OpenSpec 或 Superpowers；不新增多 Agent、Redis、独立向量数据库、消息队列。遵守现有依赖和锁文件。交付本地可审查改动，不自动推送或部署。遇到普通实现选择自行决定并记录；只有身份、产品语义无法确定或破坏性迁移等实质问题才请求澄清。

## 1. 目标与非目标

### 必须实现
- 持久化项目问答，刷新或重新进入会话后可恢复。
- 最近最多 10 个完整问答轮次，同时受 token 和总输入预算控制。
- 保存当前讨论焦点和少量有效约束，支持指代与连续追问。
- 事件触发提取值得跨轮保留的讨论记忆；去重、版本化更新、更正。
- 按需回查历史，默认采用项目范围内的对象／主题匹配和 SQLite 全文检索。
- 区分讨论记忆与源码证据；代码结论保留版本、来源和核查范围。
- 支持会话删除与派生内容清理、并发保护、幂等和失败恢复。
- 提供有界上下文组装与可检查的加载记录。

### v1 不做
- 不每轮生成整段对话摘要，不递归摘要整个聊天历史。
- 不做长期用户画像、自动掌握度评分、跨项目记忆共享。
- 不建设历史向量索引或代码知识图谱。
- 不重构简历生成检索链，不改变简历事实与评审规则。
- 不宣称完成全仓理解，不将模型建议或旧回答当作源码事实。

## 2. 现有实现接入检查

执行时验证以下位置是否仍为有效入口，不依赖旧描述硬编码：
- backend/app/interaction_service.py：context/discuss 及模型调用、版本校验。
- backend/app/interaction_contract.py：讨论输入输出契约。
- backend/app/wiki_chat.py、frontend/src/WikiOverview.tsx：Wiki 问答及前端 history。
- backend/app/agent.py、main.py：兼容 messages 接口、检查点线程身份。
- backend/app/db.py、memory.py、migrations：Message、MemoryEvent、工作区及版本机制。
- frontend/src/ProjectIteration.tsx：项目讨论调用与恢复。
- 现有 test_interaction/test_memory/test_wiki_chat 及架构边界检查。

共享会话存储和上下文组装逻辑；两个可见入口可保持独立 conversation_id，不能把历史无差别混入。若产品只保留一个讨论入口，更新所有调用方并记录旧入口兼容或移除理由。旧写操作是否仍供显式表单使用须核对；只移除聊天自动业务写入，不删除被其他入口需要的实现。

讨论检索复用现有 DeepWiki/源码能力。若外部服务将历史和新问题混成不可控制的检索输入，明确适配方式与实际预算范围，不伪称应用已控制外部模型完整上下文。

## 3. 逻辑数据模型

优先扩展现有表，以下是逻辑实体，不要求逐一建立同名新表。

### Conversation
id、workspace_id、surface、active_topic_id、focused_refs、pending_question、revision、created_at、updated_at、deleted_at。
surface 区分讨论入口；焦点可包含文件、符号、方案名称，必须来自输入或实际材料。conversation_id 持续跨消息复用，request_id 只代表一次请求。若使用 LangGraph checkpointer，thread_id 绑定会话，不能每条消息创建新线程。

### Message / Turn
复用 Message，补 conversation_id、turn_id、sequence、request_id、status、source_refs 等必要字段。
记录原始用户消息与助手最终回答；工具材料以可追溯引用保存，避免大段重复。
turn 状态：pending/completed/failed/cancelled。近期窗口只计完整成功问答；本次用户消息独立加入；失败和取消记录可查但不当作完整历史。

### Topic
项目、会话内主题身份；标题、别名、关联文件／符号、活跃状态。
主题粒度是“任务恢复”“缓存方案”，不是每条消息；比较任务可引用多个主题。

### MemoryItem
id、workspace_id、conversation_id、topic_id、scope、kind、subject_key、content、
origin、status、source_message_ids、evidence_refs、source_revision、version、
supersedes_id、created_at、updated_at。
scope：conversation/topic/workspace；仅用户明确表示适用于整个项目时才扩展为 workspace。
kind：constraint/correction/proposal_note/open_question/code_observation。
origin：user_explicit/assistant_proposal/source_observation。
status：active/resolved/superseded/needs_recheck/archived/retracted。
当前有效投影与审计历史可用现有 MemoryEvent 实现，不重复建设事件框架。
不得在 content 中保存隐式推理链，仅保存可解释的讨论结论、来源和取舍。

## 4. 每轮执行流程

1. 校验会话属于当前工作区，校验 request_id 幂等，保存用户输入及 pending turn。
2. 加载当前消息、近期完整问答、讨论焦点、适用的 active 约束及未决事项。
3. 用轻量规则处理显式入口，必要时一次结构化 LLM 解析同时产生：
   - topic_relation：continue/switch/return/compare；
   - focused_refs、standalone_query；
   - history_needed/history_query、source_lookup_needed；
   - memory_candidates（包含来源、范围和候选更新，不直接自由写库）。
4. 当前消息的明确纠正优先用于本轮上下文；若重复请求或冲突，按版本保护处理。
5. 需要历史时，在当前工作区权限范围先按对象／主题精确定位，再全文召回完整问答或短连续片段。加载前过滤撤销、被替代记录；查历史事实时可显式读取历史版本。
6. 把指代补成完整查询；保留原始问题。不得在查询里将待验证机制预设为存在。
7. 现有材料足够则复用；涉及新实现范围、新版本或证据冲突时补查源码。历史回答仅作线索。
8. 执行总预算组装并生成回答。源码证据保留出处，无法判断时说明未知；歧义只在影响答案时澄清。
9. 保存完整答案和证据引用，更新焦点、提交已校验的记忆变更。不得保存半截流式输出为成功回答。
10. 模型失败时原始消息仍可审计；用户明确约束可独立可靠提交，但助手派生观察必须依赖成功输出和有效证据。UI 不应把“约束已记录”误报为回答成功。

同一会话采用排队或 revision 乐观并发保护；不要在慢模型调用期间持有长数据库写事务。异步结果检查会话删除状态与读取版本，旧结果不得覆盖新纠正。

## 5. 长期记忆写入规则

长期记忆依据内容价值写入，不等 10 轮后搬运。
- 明确持续约束、明确更正：当前轮保存。
- 明确方案态度和理由：保存 discussion 状态，仅表示讨论态度。
- 尚未解决且影响后续的问题：保存，解决后标 resolved。
- 源码观察：仅附证据、版本、核查范围；不能因助手说过就成为已验证事实。
- 一般提问、礼貌回应、重复解释、没有明确采用的假设：仅保存原始消息。
- “解释过”不等于“用户掌握”；“继续研究”不等于“已采用”；“已采用”不等于源码已实现。
- v1 不维护独立长篇主题摘要。主题视图由有效条目组成；以后增加摘要时，它只是可重建派生数据。

结构化输出必须验证引用存在且归属当前范围。模型不能自己选择其他项目 ID、扩大权限或将检索材料中的指令作为操作授权。

## 6. 去重、合并与更正

先以 workspace/scope/topic/kind/subject_key 限定候选，再判断关系：
- 相同内容：NOOP 或补来源，不新增当前有效项。
- 同对象的无冲突补充：MERGE，新版本，保存前后内容。
- 明确纠正：SUPERSEDE，替代旧项，保留历史。
- 独立方案：ADD，不因语义相似就合并。
- 不同范围的要求：分别保留并明确适用范围。
- 冲突不明：不覆盖，标记待澄清或询问。

禁止基于相似度分数自动删除或合并。没有新的有效信息时不新增条目；更新幂等且关联 source_message_id。范围改变不能静默发生。
重要纠正同步失效相关可加载投影；检索命中的旧条目解析到当前有效版本。较新的助手意见不能替代用户明确约束。

## 7. 加载与预算

配置起始值（可调整，不是质量保证）：
- MEMORY_RECENT_TURNS=10
- MEMORY_RECENT_TOKEN_BUDGET=4000
- MEMORY_STATE_TOKEN_BUDGET=1200
- MEMORY_HISTORY_TOKEN_BUDGET=2000
- CHAT_INPUT_TOKEN_BUDGET=16000
- CHAT_OUTPUT_TOKEN_RESERVE=2000
- 有效输入上限=min(应用输入预算, 模型窗口-输出预留-安全余量)。

计数覆盖真实应用 prompt 的规则、工具 schema、用户消息、近期问答、状态、历史和证据，不只数聊天文本。能获得 tokenizer 时准确计数；否则明确标记保守估算，未知实际 usage 不报零。
源码使用剩余预算；上游服务内部 prompt 不可见时，记录可控制范围及未知量。

超预算处理顺序：
1. 去掉重复证据、无关召回。
2. 移出较旧完整问答，保留近期必要轮次。
3. 缩小源码窗口，保留来源与按需回读能力。
4. 动态选择相关状态，所有有效状态仍在数据库，不因输入预算被删除。
5. 当前问题或必需材料单独超限时，明确提示缩小范围或分段处理，不静默丢弃。

核心约束与当前纠正优先于旧解释。若有效约束太多，按当前主题选择；无法在预算内可靠回答则澄清或缩小任务。
仅切换话题不触发摘要调用。滚动摘要不属于 v1 的必需实现；保留可扩展点但不提前建设后台摘要基础设施。

## 8. 历史检索与源码版本

历史读取：topic/object 精确匹配 → SQLite 全文搜索 → 返回完整轮次及必要相邻轮次。
中文全文检索必须有验证：检查当前 SQLite 的 tokenizer 能力；可采用适用的 tokenizer 或显式关键词回退，不假设默认英文分词能覆盖中文。缺能力时暴露受限模式并测试，不静默空召回。
仅在“返回旧主题／比较／指代无法解析／追问原话”等需求下召回，不每轮搜索全部历史。
数据记录 source_revision；版本变化时 code_observation 标 needs_recheck。约束和方案讨论仍保留，但不声称对新版本已成立。
DeepWiki 索引版本不能确认时记录 unknown。应用记录 SHA 不等于外部索引绑定 SHA。
复用源码证据需身份、版本和范围匹配；不能只比较问句相似度。

## 9. 删除、归档及原文保留

- 切换主题：退出活跃上下文，不删除。
- 问题解决：resolved，默认不作为待办加载。
- 更正：superseded，历史可查。
- 长期不活跃：可归档，不以访问少自动撤销用户约束；v1 不需要定时归档任务。
- 默认不自动按天数删除原始对话；保留行为在界面说明，提供删除会话和项目记忆能力。
- 删除会话：立即禁止加载；清理消息、仅由该会话支持的记忆、全文索引、缓存和检查点。
- 多来源共享条目：去掉被删除的来源；仍有独立有效来源才能保留，重建内容，防止删除的信息残留。
- 删除项目：清理本记忆模块的项目数据，复用现有项目删除生命周期。
- 正在运行的任务不得在删除后重新写回；晚到结果检查 tombstone/revision。
- MemoryEvent 中如果含被删除的内容，必须随保留策略清理或脱敏，不把审计当作逃避删除的副本。

## 10. API 与前端契约

按现有风格定义最终路由并更新所有消费者，不要求固定 URL：
- 建立／恢复会话；分页读取消息。
- 发送问题：conversation_id、request_id、expected_revision、content；客户端 history 不再充当权威历史。
- 获取当前讨论焦点与可查看的记忆条目。
- 删除会话及其派生记忆；项目记忆清理入口。
- 用户可看到保存的约束／讨论笔记并纠正或删除，避免黑箱记忆。

保留流式回答；刷新从服务端恢复。用户主动停止后标 cancelled，不伪造完成。兼容旧 history 参数若必须保留，限定过渡期并记录用途，不把任意客户端历史写为真实已发生记录。
旧消息回填采用可识别的 legacy 会话或其他明确迁移策略；旧数据不得丢失，不能仅根据文本猜来源入口。

## 12. 质量评测与成本

提供30–50个多轮场景的 fixture 与运行脚本；先覆盖20个验收类别，部分超过10轮。每例标注当前对象、必须保留约束、必要历史与源码证据、禁止断言、是否需要澄清。
A：近期10轮+总预算；B：A+当前状态；C：B+动态历史检索+查询改写。
使用相同模型、固定源码证据和相同总预算；评测数据不混入提示调参示例。
报告：对象识别、约束遵守、更正使用、必要历史召回、最终上下文覆盖、错误记忆使用、方案状态保真、回答依据、每轮token和延迟。区分检索命中和预算裁剪后真正输入。
关键安全／数据规则（隔离、删除、幂等、版本冲突、来源）离线测试必须全通过。
真实模型质量不预设虚假达标值：报告原始分子分母、失败例、基线差异及限制；无真实运行则标未执行。调用真实付费服务须遵循仓库授权规则，不能为了交付自动消耗。
每轮日志至少包含 memory_ids、history_message_ids、evidence_ids、selection_reason、omitted_reason、token_estimate、revision 和检索／改写次数，不记录密钥，不记录隐式思维链。

## 13. 实施顺序与完成定义

1. 盘点当前入口与消费者，形成简短差异清单；确定复用与迁移策略。
2. 实现会话身份、消息持久化、恢复和幂等；补迁移及行为测试。
3. 实现上下文预算与当前状态；验证完整轮次和前端恢复。
4. 实现候选记忆校验、去重、更正与事件关联。
5. 实现按需全文历史检索和查询改写，接入现有源码检索适配。
6. 实现删除、晚到结果保护、版本待复核。
7. 运行相关后端、前端类型与架构检查；按当前 AGENTS 要求执行适用总检查。
8. 同步 PRODUCT、architecture、DECISIONS、STATUS 当前节；避免复制一套冲突文档。
9. 将配套精简 README 放到 docs/memory/README.md，规格放到 docs/memory/spec.md；根 README 加短简介或链接，不覆盖现有项目介绍。
10. README 只有在实现及验证后才改成“已实现”，未跑真实模型评测必须保留说明。
